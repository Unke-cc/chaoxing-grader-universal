## 一、工作原理解析

### 传统批改的痛点
- **高分扎堆/两极分化**：人工批卷或普通脚本容易导致全班扎堆在 90+ 分，或缺乏区分度；
- **及格线拦截中断**：超星学习通平台默认设置了 60 分及格线拦截机制，若学生得分低于 60 分，系统强制弹出打回重做弹窗，中断自动化批改流水线；
- **分页断裂与漏评**：超星列表页默认仅展示 20 行，翻页容易因异步加载延迟导致跨页漏评或重复评分；
- **界面切屏与焦点抢占**：传统操作系统级脚本在执行时频繁抢占键盘鼠标焦点，导致教师无法在前台正常办公。

### 本工具的技术解决路线
- **协议级 CDP 直连**：直接通过本地 WebSocket 与 Chrome 的 Blink 渲染管线交互，全程后台静默，**浏览器可直接最小化**；
- **正态分位数动态映射**：严格按实际已交人数 $N$ 为基准，科学分配优秀（18%）、良好（44%）、及格改进（38%）比例；
- **及格线底线保护与限分压制**：硬性执行最低分 $\ge 60.0$ 分，支持名单上限拦截；
- **前置 100 行单页化**：单页全量加载，消灭不必要的分页等待。

## 二、环境准备与浏览器启动

### 1. 安装 Python 依赖
```bash
pip install -r requirements.txt
```

### 2. 启动 Chrome 调试模式
为了让脚本安全通信，需要让 Chrome 开启本地调试端口（默认为 9222）。请在各系统终端中执行对应命令：

#### 💻 Windows 系统
```cmd
"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --remote-allow-origins=*
```
> **快捷启动技巧**：右键桌面 Chrome 图标 -> 属性 -> 在“目标”一栏末尾追加一个空格及 `--remote-debugging-port=9222 --remote-allow-origins=*`，以后双击该快捷方式即可直接启动。

#### 🐧 Linux 系统
```bash
google-chrome --remote-debugging-port=9222 --remote-allow-origins=* &
```

#### 🍎 macOS 系统
```bash
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --remote-debugging-port=9222 --remote-allow-origins=* &
```

### 3. 登录超星教师端并定位作业
1. 打开浏览器访问 `https://i.chaoxing.com/base` 并登录；
2. **核心权限入口**：在课程区域必须点击【**我教的课**】（ID 为 `#myTeach`），进入具备管理权限的主页；
3. 进入对应课程的“作业管理”，点开需要批改的作业，进入“批阅列表页”。

### 4. 连接自检
在终端运行诊断命令：
```bash
python scripts/grade_engine_cdp.py --check
```
当终端提示 `[CDP 连接状态] 成功连接到浏览器...` 且能正确识别超星标签页时，即可开始批改。

## 三、标准批改两阶段流程

为了保障给分安全与教学合规，本技能严格执行**“先审核、后入库”**的两阶段流程：

```
       [教师发起批改请求]
               │
               ▼
   [阶段一：只读测算与审核把关]
   ├─ 自动将列表切换至 100 行/页全量加载
   ├─ 只读提取全员主客观作答与实验报告
   ├─ 大模型依据学科标准答案逐题评审排序
   ├─ 按已交人数 N 正态分流映射分数
   ├─ 自动核查 60 分保底与特定学生限分
   └─ 输出《全班成绩核对总表》与学情统计
               │
         教师审查核对单
        （确认无误后回复）
               │
               ▼
   [阶段二：指令确认后批量入库]
   ├─ 途径 A（批阅详情页）：小题细分填入 + 综合评语 + markAction(1)
   └─ 途径 B（批阅列表页）：单页 input.scoreInput 批量改分触发存盘
```

## 四、正态分布分流与限分规则

### 1. 动态三档比例设计
以当前作业实际提交人数 $N$ 为基数：

| 分数区间 | 分段定位 | 占已交人数比例 | 分布说明 | 对应匹配作业总评语 |
| :---: | :---: | :---: | :--- | :--- |
| **$90.0 \sim 95.0$ 分** | **优秀拔尖档** | **15% ~ 20%** | 作业出色，步骤与逻辑完整达标 | `作答规范，思路清晰，值得表扬` |
| **$80.0 \sim 89.5$ 分** | **良好稳定档** | **40% ~ 45%** | 掌握核心知识，存在微小瑕疵 | `基础扎实，作答良好，继续保持` |
| **$60.0 \sim 79.5$ 分** | **及格改进档** | **35% ~ 40%** | 有明显未答题或错误（充分覆盖 60~79 分） | `作业完成规范，有部分需要改正，继续加油` |

### 2. 60.0 分及格线底线保护
超星系统设有及格线强制拦截机制。即使学生作答极差，系统也会自动赋予 60.0 分保底分，防止弹出打回重做窗口阻断自动化。

### 3. 特殊学生限分配置
在前置确认时，如果某位学生因考勤缺卡或违规需要限分（例如指定“张三”最高不超过 85 分）：
- 只需向 Agent 说明：“张三不超过 85 分”；
- 引擎在算分后会自动检查该名单，超出的分数一律自动压制在 85.0 分以内。

## 五、实验报告多维批阅指南

针对实验课上交的 Word、PDF、ZIP 或超星云盘挂载附件，量规按以下四维度评分：

1. **报告规范度 (20%)**：目的明确、环境齐全、包含班级姓名学号；
2. **核心技术实现 (50%)**：代码逻辑契合度、框架使用准确度、功能完整性；
3. **运行效果佐证 (20%)**：包含真实完整的控制台输出或软件运行界面截图；
4. **实验思考总结 (10%)**：实验技术总结与问题排查反思。

对应实验评语范例：
- 优秀档：`实验步骤完整，项目搭建规范，运行效果良好，值得表扬`
- 良好档：`基础扎实，实验完成规范，继续保持`
- 改进档：`实验报告基本完成，部分细节与截图有待完善，继续加油`

## 六、大班级（>100人）调度机制

1. **普通自然班（$\le 100$ 人）**：
   通过 URL 参数携带 `size=100`，全班单页一次性读取完毕，零翻页。
2. **合班教学/大班级（$> 100$ 人）**：
   系统自动检测单页是否抓满 100 人。若满 100 人，将以 100 行为步长自动自适应翻页至第二页（`pages=2`）、第三页（`pages=3`）继续处理，每页批量入库后预留充分等待时间（4.0 秒以上）以保障超星服务器存盘入库。

## 七、常见问题与排查指南 (FAQ)

### Q1: 执行时提示 `无法连接到 Chrome CDP (http://127.0.0.1:9222)`？
- **原因**：Chrome 没有开启远程调试端口，或者已被其他进程占用。
- **解决方法**：完全关闭现有的 Chrome 浏览器（确保后台无残留进程），重新按照前文命令带 `--remote-debugging-port=9222` 启动。

### Q2: 提示 `未检测到包含 chaoxing.com 的标签页`？
- **原因**：Chrome 中尚未打开超星教师端，或者处于登录界面（`passport2`）。
- **解决方法**：在 Chrome 中登录超星并进入作业列表页或批阅页，再重新发起批改。

### Q3: 为什么有的学生分数会比我预期的稍低或稍高？
- **原因**：系统执行的是正态分布分位数动态映射。如果全班整体完成度都很高，系统也会按既定比例将表现相对靠后的学生适度平滑映射到 60~79.5 分区间，以满足高校教学大纲关于成绩正态分布的硬性考核指标。

### Q4: 列表页批量给分后，刷新页面发现没有保存？
- **原因**：超星输入框改分依赖触发 `blur` 失焦事件以及后续的 AJAX 异步网络请求。
- **解决方法**：引擎在批量填入后默认预留了 4.0 秒的写入缓冲等待。请勿在脚本刚执行完毕时立即刷新页面或强行关闭浏览器。
